Rule of the system: only the HHT may do a physical transaction (scan, move, PDI, gate, slip). The web is for masters, uploads, release, challan, approval, reports and monitoring.

stateDiagram-v2

  HELD --> ALLOCATED: scanned on Empty Pallet Return
  ALLOCATED --> IN_TRANSIT: OUT gate (empty return)

  DAMAGED --> UNDER_REPAIR
  UNDER_REPAIR --> AVAILABLE
  DAMAGED --> DISCONTINUED

Alongside the status, every pallet carries a zone inside the plant (Yard · Production · FGWH · Packing) and a load state (LOADED / EMPTY). The Yard holds empty pallets only.

  1. Web › Pick Lists › New: type CUSTOMER or STOCK_TRANSFER, blanket order, part qty, pallet qty.System: refuses if WMS stock is older than the plant limit or the blanket has no open qty. Reserves LPNs oldest first. Status OPEN.
  2. HHT › Dock Out-ward Scan: pick the list, scan the LPN label or the pallet. One pallet can carry several LPNs.System: LPN fetches its pallet; pallet fetches its LPNs. Pallet must be in FGWH / Packing (a skipped move is recorded and corrected). Pallet ALLOCATED, LOADED. A rejected scan disappears from the HHT list.
  3. HHT › Confirm → send to PDI when picked qty = part qty.Status PDI_PENDING.
  4. HHT › PDI Check: mark each LPN OK or reject; complete.Rejected LPNs go to the reject sub-inventory and the list reopens for the balance. OK LPNs move to the customer / part sub-inventory; each move needs EBS acceptance and an on-hand read-back. Then the SO is pushed. Status READY.
  5. Web › Challan.Invoice number fetched from EBS first; challan printed from the web (A4) with invoice and LPN lines.
  6. Web › Approve: vehicle, transporter.GCS outward gate pass created. Status APPROVED.
  7. HHT › OUT Gate: scan the GCS / challan QR.Must match the pick list (supervisor PIN to override). Pallets AT_CUSTOMER with dispatch date; LPNs DISPATCHED. Status DISPATCHED.

  1. Slip: Mode A comes from the customer's system with a signed QR; Mode B1/B2 is made on the HHT at the IN gate and printed on the portable printer.Pallets on an A / B1 slip go IN_RETURN. A label without a valid check code is refused at the gate ("HOLD VEHICLE").
  2. HHT › IN Gate: scan the slip QR; optionally type the vehicle number.Check code, plant, customer and vehicle verified; GCS inward pass; slip IN_GATE.
  3. HHT › Yard In-ward Scan: open the slip, scan every pallet; mark damaged if needed.Pallet AVAILABLE (or DAMAGED), EMPTY, zone Yard. Not on the slip → EXCESS / CROSS_CUSTOMER; another plant's → HELD. A pallet that was never gated out is accepted and the missed OUT-gate scan recorded.
  4. Reconcile & close.Short pallets go back to AT_CUSTOMER keeping their aging; open exceptions need a supervisor PIN. Slip CLOSED.

  2. HHT › Internal Movement as the material is used, ending with Packing → Yard.Pallet HELD, EMPTY in the Yard.
  3. HHT › Empty Pallet Return › New: pick the owner plant (count shown), enter the vehicle, scan the pallets as they are loaded.Only that plant's empty pallets are accepted; open quantity. A pallet not scanned into the Yard is still loaded and the missed move recorded.

Each route is a separate right granted per user. When a scan point finds a pallet where it should not be, the system takes the safe reading, corrects the ledger and writes a Missed Scan with the responsible role. The HHT shows the alert at once; the web lists them under Stock & Movement › Missed Scans and on the Daily Exception Report.

6New pallet label and pallet care

The pallet label QR holds a record: uniquePalletID AIS-<plant>-<type>-<serial>-<global>, ownerPlant, palletType, mfgDate. Every scan point reads it.

  1. HHT › Yard In-ward Scan (no slip): scan each new label.Pallet created from the QR: own plant → AVAILABLE in the Yard; another plant's → HELD here. Owner plant not in the Plant master → quarantined with the reason.
  2. HHT › Damage / Tag issue: mark damaged or request a tag replacement.DAMAGED → UNDER_REPAIR → AVAILABLE or DISCONTINUED (web, central).

TTest checklist

Run on one plant with two or three pallets, one LPN pick list and one return. Tick as you go; ticks are kept on this device only.

When a step fails, note the HHT message word for word and the time; the server's Activity and Sync Monitor pages show the same event with the reason.
